# M1 — Walking skeleton (implementation)

This is the running implementation of **Milestone 1** from [`README.md`](./README.md):

> **Build:** one-box bootstrap · oauth2-proxy → Google, company-domain-restricted ·
> kiosk skeleton (upload → safe-unzip → detect → LLM Dockerfile gen +
> build-verify-heal + Trivy + push → app-from-image) · Traefik routing + TLS ·
> LiteLLM up, kiosk's own calls redacted → LiteLLM · Slack escalation +
> append-only audit table.
>
> **Done when:** a trivial **Node** ZIP *and* a **Python** ZIP each go drop →
> live URL behind Google login, Dockerfile LLM-generated, the heal loop
> recovering ≥1 induced failure; a non-company Google account is denied.

The deploy engine is **Coolify**: the kiosk builds + pushes the image, then
drives Coolify's REST API to deploy it (see
[`coolify/README.md`](./coolify/README.md) and `kiosk/app/backends/coolify/`).
The build/heal pipeline, redaction, auth chain and audit below are
engine-agnostic — Coolify only replaces the hosting step — because M1 kept the
two seams: **everything routes through Traefik + auth**, and **every app is an
image from a Dockerfile**. (Earlier drafts shipped a plain-Docker deployer; that
legacy path has been removed in favour of Coolify.)

## Bring-up

Coolify is the deploy engine + ingress, so bring-up is: install Coolify, then
start the shared services the Kiosk drives. The full runbook (project /
destination / token setup, the auth-chain middlewares, the parity gate) is
[`coolify/README.md`](./coolify/README.md); in short:

```bash
cd platform
sudo coolify/install.sh   # Coolify (host-as-code, pinned)
# then in the Coolify dashboard: project + environment + destination + API token
make .env                 # copy .env.example -> .env; set OPENROUTER_API_KEY +
                          # the COOLIFY_* vars (KIOSK_LLM_MODE=stub for offline)
make up                   # shared services: authstub/oauth2-proxy + kiosk +
                          # litellm + registry + postgres (Coolify fronts ingress)
make samples              # zip the Node + Python fixtures into ./dist
```

Open the Kiosk (exposed via Coolify at `kiosk.$PLATFORM_DOMAIN`), drop
`dist/node-hello.zip`, and watch the build-verify-heal log stream; the Kiosk
builds + pushes the image and Coolify deploys it. Repeat with
`dist/python-hello.zip`.

**Done-when parity gate** (run on the box, per `coolify/README.md`): both samples
reach a live URL, a non-company account gets `403`, and — with
`KIOSK_LLM_MODE=llm` + `KIOSK_INDUCE_BUILD_FAILURE=1` — the heal loop recovers
the induced failure.

## Switch to real Google (EC2 / staging)

See [`docs/AUTH.md`](./docs/AUTH.md). In short: set `AUTH_MODE=google`, fill the
`OAUTH2_PROXY_*` vars, register the redirect URI, then `make up PROFILE=google`.
oauth2-proxy enforces `--email-domains=$COMPANY_EMAIL_DOMAIN`, and the kiosk
enforces the same domain independently — so "non-company account denied" holds
at both layers.

## The pipeline, end to end

`orchestrator._run` is the saga:

1. **audit** `app.create` (actor = Google identity).
2. **safe-unzip** — rejects zip-slip, absolute paths, symlinks/specials, and
   over-limit/over-count archives; descends into a single wrapper dir.
3. **detect** — deterministic runtime/framework/shape/port read. The LLM
   *proposes*; this *anchors* (README §8: "LLM proposes, structure guarantees").
4. **redact** — every manifest file and the dir tree are secret-redacted
   *before* any bytes reach the LLM (README §9's governed-egress fix).
5. **build-verify-heal** (`builder.Builder.run`):
   - enforce the base-image **allowlist** (structural, not LLM-trusted);
   - **build** the image;
   - **verify** by *booting* it on the internal backplane and probing the port —
     this catches crash-on-start failures a build alone misses;
   - on any failure, feed the captured output back to the model and retry,
     capped by `KIOSK_HEAL_MAX_ITERATIONS` **and** a shared
     `KIOSK_LLM_TOKEN_BUDGET` (denial-of-wallet guard);
   - **Trivy** scan (informational at M1) then **push** to the registry.
6. **deploy** the pushed image with Traefik labels → hostname + TLS, behind the
   `forwardauth` middleware (private by default).
7. **record** success/failure in the catalog + audit; failures **escalate** to
   Slack with a plain-English reason (never a raw stack trace to the creator).

## Verifying the heal loop

The done-when needs the heal loop to recover ≥1 induced failure. Rather than
depend on model luck, `KIOSK_INDUCE_BUILD_FAILURE=1` poisons the *first* build
(`RUN … exit 7`) so attempt 1 fails and the model must repair it on a later
attempt — a genuine heal driven by the real error output. Uploading a sample
with that flag set makes a second attempt appear in the build log. This requires
`KIOSK_LLM_MODE=llm` (the stub can't reason about errors — it says so).

## Security posture honored at M1

From README §9's "top fixes", the ones in scope for M1 and where they live:

- **redact-before-LLM** — `redact.py`, applied in the saga before generation.
- **base-image allowlist + Trivy** — `baseimages.py`, `builder._trivy`.
- **network segmentation** — a `backplane` (internal, no egress) for
  kiosk↔postgres↔litellm↔registry; tenant apps live only on the `proxy` net and
  reach the platform through Traefik hostnames, not shared datastores.
- **strip inbound `X-Auth-*` + company-domain enforcement** — `strip-auth-in`
  middleware (anti-spoofing) chained before `forwardauth`, plus `auth.identity`.
- **safe extract / no secrets in image** — `zipsafe.py`; the generation prompt
  forbids `COPY .env` and secret-bearing build args.
- **append-only audit** — a Postgres trigger blocks UPDATE/DELETE on `audit`.

**Accepted at M1 (matches README §9):** no gVisor/full build sandbox — build-RCE
is *contained* by the allowlist + segmentation, not eliminated. The build worker
still shares the API process's Docker socket (DooD); **isolating the build worker
is a lean-v1 item**, noted here so it isn't mistaken for done.

## Deliberately deferred to lean-v1 (not M1)

Per the README scope table, M1 does **not** include: per-tenant Postgres +
injected `DATABASE_URL`, per-app allow-lists, cron, per-tenant LLM virtual keys,
egress-deny + outbound allowlist, Coolify-managed DB backups, Uptime-Kuma + disk
alert, and the reconciler. Each hangs off the seams M1 establishes. The M1 audit
table already carries the owner field the catalog needs.

## Verified live

> **Historical.** The run below validated the pipeline against the original
> plain-Docker deployer, which has since been **removed** in favour of Coolify.
> The pipeline steps (unzip → detect → redact → build → verify → heal → audit)
> are engine-agnostic and unchanged; only the final hosting step moved to
> Coolify. The current bar is the Coolify parity gate in
> [`coolify/README.md`](./coolify/README.md).

The full pipeline was run end-to-end against a real Docker daemon:

- **Node ZIP → live URL behind login** — `https://node-hello.apps.localhost/`
  served `hello from node-hello` through Traefik + forward-auth (HTTP 200);
  pipeline log showed unzip → detect → redact → Dockerfile → build → **verify
  booted the container and got HTTP 200** → deploy.
- **Python ZIP → live URL behind login** — same, serving on `:8000`.
- **Verify catches crash-on-start** — a Python app missing a runtime dependency
  built fine but crashed on boot; verify detected the exit and invoked the heal
  loop (which, in `stub` mode, honestly reports it can't heal and escalates).
- **Non-company account denied** — pointing the dev identity at
  `intruder@gmail.com` returned `403 access denied … is outside @wego.com`.
- **Append-only audit** — `app.create / detect / build / deploy` rows recorded,
  actor = the Google identity.

Two items need a real model and so were exercised in `stub` mode here: **LLM
Dockerfile generation** and **heal recovering an induced failure**. Set
`OPENROUTER_API_KEY` + `KIOSK_LLM_MODE=llm` (and `KIOSK_INDUCE_BUILD_FAILURE=1`
for the heal) and re-run the parity gate to validate both against the model.

### Note: Traefik + Docker Engine ≥ 29

Docker Engine 29 raised its minimum client API version to 1.40. Traefik ≤ v3.5's
docker provider pinned API 1.24 without negotiation, so on a v29 daemon it
couldn't read container labels (`client version 1.24 is too old`). **Fixed by
pinning `traefik:v3.6`** (committed), which negotiates the API version — verified
label routing works end-to-end on Docker 29.3.1. No socket proxy or file-provider
workaround needed.

## Environment notes

- Requires a Docker daemon on the box; the kiosk builds and runs tenant
  containers via the mounted host socket (docker-out-of-docker).
- The registry push is **best-effort**: on one box the daemon already holds the
  built image, so deploy works even if push is skipped. To make the push
  succeed (honoring the deploy-from-image contract fully), add `registry:5000`
  to the daemon's `insecure-registries` (`/etc/docker/daemon.json`) or front the
  registry with TLS. A skipped push never fails a provision.
- `make check` runs a no-daemon sanity pass (`compileall` + `docker compose
  config`). The dependency-free safety modules (redaction, allowlist, safe
  extract, detection) are unit-testable without Docker/Postgres.
- `.env` and `dist/` are gitignored; nothing secret is committed.
