Engineering · Platform · Decision Brief

Where internal apps run

A self-serve platform where non-engineers drop a ZIP and get a hosted internal app — database, cron, Google login, per-app access control, and optional AI — on Coolify.

Status · Planning / design Engine · Coolify (Apache-2.0) Trust · Trusted-internal, accident-hardened Runs on · Colima (local) & EC2 (internal)
Core principle — two planes. Creators (non-engineers) only ever use the Kiosk (user-facing). Operators (engineers) use the Coolify dashboard as the admin console. The Kiosk drives Coolify through its API on the creator's behalf — nobody non-technical touches Coolify.

The problem

Useful internal tools keep getting built with nowhere proper to run them

The moment something has a backend, a database, or per-user access, it stalls — waiting on an engineer to deploy it. This is the blessed, self-serve path that closes the gap.

What a creator does
  • Sign in with company Google
  • Name the app, drop a ZIP
  • Confirm roles, public/webhook paths & outbound domains
  • Paste any API keys
What the platform does automatically
  • Redacts secrets, detects the stack, generates a Dockerfile, builds + scans
  • Provisions a per-tenant database, AI key, bucket, mail creds
  • Wires cron, roles, egress; deploys with a URL + TLS
  • Classifies data, backs up, streams logs into the Kiosk

The user plane

The Kiosk — designed, deployed, self-monitoring

Design

UI · orchestrator · reconciler (GCs orphans) · build workers (allowlist + Trivy) · detect + LLM (redact → LiteLLM) · catalog · lifecycle · audit · observability. State in Postgres; rest stateless.

Deployment

Dogfooded — a Coolify app behind oauth2-proxy, least-privilege token, build workers isolated from it. Stateless replicas for HA; proxy + authz replicated.

Monitoring

Surfaces each app's Coolify logs, health & deploys to creators; tracks build status, AI spend, activity; writes audit; feeds operator dashboards.

Access control

Per-app RBAC — route-precise, honest about the rest

Guaranteed

Route + method → role, default-deny, at the proxy with zero app code. A missed route is denied. A Viewer can't reach /admin.

Hybrid for server actions

Server-action POSTs (marked Next-Action) are held to the highest role = Admin-only; GET nav & /api/* keep per-path rules. Write-heavy apps are flagged at confirm to move mutations to /api/* so Editors can write. GraphQL/ws → coarse gate.

Row-level

Opt-in Postgres RLS (no filter code; deny-when-unset) — same class as operation-level: fine granularity needs the DB or app cooperation.

LLM proposes, structure guarantees. Classification, role proposal, and server-action detection all rest on deterministic defaults (default-deny routes, default-coarse/hybrid RBAC, an egress boundary for customer data) + a detector eval harness. An LLM miss changes friction, not safety.

Day-0 operations

Built in from the start, not bolted on later

Backup & DR

Cluster WAL to S3 (per-tenant RTO = restore + extract db); Coolify's own state backed up + restore runbook + host-as-code. DR drill on Day-0.

Availability (honest)

authz serves from a local cache with staleness bounds so metadata-DB blips don't down every app. Single box shares host fate — real PG HA arrives with server #2.

Data classification

Structural first: default-deny egress + an explicit grant to reach customer systems is the signal → a miss can't expose. Content scan is defense-in-depth.

Egress & webhooks

Outbound domain allowlist (Stripe SDK ⇒ api.stripe.com), creator-confirmed. Webhooks: platform allowlists the path; the app verifies the provider signature.

Lifecycle & audit

Owner+team; activity → sleep → archive → delete; fleet catalog. Google-Groups roles + short session TTL. Append-only audit attributed to the Google identity.

Disk & DB guards

Image GC + volume quotas + disk alerting; shared-Postgres connection limits, statement timeouts, per-db size quotas — no noisy neighbors.

Delivery

Sequencing, pilots & cost — for buy-in

Day-0 defines the scope; this defines the build order. The Kiosk is several engineer-months — Coolify removes ~60–70% of plumbing, but the remaining 30–40% (orchestrator + reconciler, build/heal, detection, authz + manifest, lifecycle, audit, observability) is the hard, novel part.

  1. Walking skeleton — ZIP → LLM Dockerfile → build+scan → deploy behind oauth2-proxy. No RBAC/DB/lifecycle. + a minimal escalation surface (Slack + table).
  2. + Data & secrets — per-tenant Postgres + secret store. → Pilot 1: Leaderboard (easy path).
  3. + RBAC & machine access — authz + manifest + webhook/machine-token + server-action detection.
  4. + AI governance — LiteLLM per-tenant keys.
  5. + Day-0 ops — backup/DR, authz cache, disk/DB guards, reconciler, classification, audit, lifecycle. → Pilot 2: ADM Tracker (hard path).
  6. + Polish — cron semantics, email, storage, preview-before-promote, rebuild cadence, escalation queue UI.
Minimal start — one box. M1 is a small footprint: one Colima VM / small EC2 running Coolify (or plain Docker) · Traefik · oauth2-proxy · Kiosk skeleton · LiteLLM · one Postgres. Coolify path bootstraps via installer + host-as-code; plain-Docker via one docker compose up. Do the dev-auth stub first for local. One-box → fleet later is additive, not a migration (Traefik hostnames + Dockerfile contract).

Success metrics — apps migrated off off-platform hosting · time-to-first-deploy · % builds healed without human · self-serve completion rate · uptime · mean restore time (DR drill).

Ownership assumption (a sponsor decision). This presumes a staffed, on-call owner — the brief's Path C. A free-time / Path B owner can build the walking skeleton but can't carry the Day-0 operational commitments (SLA, DR drills, upgrade cadence).

Security posture

Secure for its model — honest about what's contained

Secure for the trusted-internal, accident-hardened model with the fixes below. Two "arbitrary code on the shared host" risks are contained, not eliminated (gVisor excluded); customer-data apps are kept off this tier by policy.

Tension

Untrusted input (the ZIP) meets a privileged operation (the build) — so fixes hold regardless of trusting authors.

Kiosk LLM egress

The platform's own inference is governed: secrets redacted before any LLM sees the ZIP; calls go through LiteLLM (ZDR).

Top fixes

Allowlist + Trivy scan; platform services via Traefik hostnames (tenant nets hold no datastores); strip inbound identity headers; fail-closed authz.

Still open

What we're not claiming is settled

  • Coolify Destination creation via API — assignment confirmed & immutable; the creation path is a spike.
  • Detector eval harness & recall targets — build the labeled + red-team corpus; calibrate confidence.
  • Metadata-PG HA + authz cache staleness bounds — design + test.
  • Machine-token lifecycle — who issues, scope, rotation/revocation; sketch before M3.
  • Tenant-scoped AI cache — verify isolation with a two-tenant identical-prompt test.
  • gVisor / build sandbox — excluded for simplicity → the contained risks; reopen for adversarial, internet-facing, or customer-data apps.
